# Local Chat Studio acceptance rehearsal 2

This is our actual local-model **development acceptance rehearsal**, not a
representative accuracy benchmark. It was run on 25 October 2026 in the client's
Asia/Calcutta timezone; the raw timestamps use UTC on 24 October.

The [raw receipt](live-acceptance.json) records **10 real model generations**
through the website's HTTP API. All **13 operational checks** and **six narrow
fixture assertions** passed. These are overlapping assertions about the same
small workflow, not 19 independent questions, 19 edits or a general success rate.
They are also separate from the 44 contract unit tests that use small fixtures
or fake model backends.

The ten generations were:

1. A normal text explanation of green leaves.
2. A conversational follow-up asking for a simpler explanation.
3. A question about an unknown synthetic registry fact before publication.
4. The same question after an explicit administrator publication.
5. A paraphrase using that correction.
6. An unrelated question about Japan's capital.
7. The original-model half of a matched comparison.
8. The correction-enabled half of that comparison.
9. The question after the correction was withdrawn.
10. A question about a simple synthetic image.

The operational checks verify nonempty generation, persisted conversation,
publication, selected correction identity, an unrouted unrelated question,
matched original/corrected routing, withdrawal and knowledge revision changes.
The six fixture assertions separately check direct and paraphrased whole-answer
aliases, paraphrase routing, non-endorsement of the supplied code after
withdrawal, and the reviewed Japan/image answer aliases. Their definitions are
in the raw receipt and `scripts/verify_chat_live.py`. A successful routing check
does not by itself establish a correct generated answer.

## Data and model limitations

`Aster Demo Registry` and its `LUMEN-73` code are controlled synthetic test data,
**not a real credential or private system**. The supplied source says so.
The direct and paraphrased corrected answers endorsed that code. After
withdrawal, the model stopped endorsing it but generated an unsupported different
code, `ASTER-001`. The narrow non-endorsement assertion passed; that new answer
was not established as factually correct. This failure must remain visible when
discussing what withdrawal accomplishes.

The image was generated by ordinary drawing code: a 600-by-300 white canvas,
a red square on the left at `(55,65)` to `(215,225)`, and a blue circle on the
right at `(365,65)` to `(525,225)`. It is a geometry fixture rather than a
photographic vision benchmark. The question asked for the left square's color;
the model answered that it was red. The exact generated PNG SHA256 is
`a668660962778d9c29fcce2b69ceb5257e1084a5746d91dd2b39ac5e136260d1`.

Normal text and the follow-up were inspected as generated outputs; nonempty
generation is not a comprehensive factual-quality assessment. The correction
retriever's `.72` cutoff is a chat development setting, not a probability or a
validated accuracy guarantee. No independent human label review or broad chat
evaluation is claimed.

## Earlier failure and context policy

The [first local rehearsal](../chat-studio-local-1/live-acceptance.json) passed all
13 operational checks while its direct corrected answer repeated an earlier
refusal. Its [qualitative review](../chat-studio-local-1/qualitative-review.json)
preserves that model-answer failure rather than relabeling the run as accurate.

The new policy excludes **all assistant messages from earlier knowledge
revisions**, including earlier refusals and base answers, from later model
prompts. It also excludes correction-conditioned assistant messages. The complete
visible conversation stays in SQLite. This reduces stale-answer anchoring but
can reduce continuity when a user refers to details supplied only in an older
assistant response. User messages remain subject to the bounded context window.

`77b50f7dedd156c36f81d94edf79302e4aa8d784`. This is the **base HEAD**, not a

The models were `qwen3-vl:2b-instruct` and `all-minilm:22m`, with actual identities

snapshot, not an allocator peak or a measured training-memory requirement.
The models were pretrained; this rehearsal performed no training or parameter
editing. It tested approved external correction memory and generated responses.

show the controlled Australia counterfactual: Canberra before, explicitly
fictional Melbourne when supplied, and Canberra after withdrawal. That browser
demonstration is not part of the ten-generation acceptance count and is not a
real-world factual update.

The frozen BLIP-2/MEND **20-edit / 500-answer** experiment is unchanged and
remains separate. Its accuracy numbers do not transfer to this Qwen chat model.
Container build/HTTP checks, when recorded by CI, are separate engineering
evidence and establish neither GPU-container inference nor model quality.
