# Matched operations development run

These are **120 actual model requests**: the same 24 questions in each of five
configurations, spanning three predetermined fictional development lineages.
The full dataset has 16 development lineages; this bounded run does not evaluate
all of them. It is development evidence, separate from the held-out final study.

| Configuration | Correct / assigned | Wrong | Abstained |
| --- | ---: | ---: | ---: |
| ReasonKE, initial facts (R0) | 12/24 | 12 | 0 |
| ReasonKE, updated retrieval (R-RAG) | 24/24 | 0 | 0 |
| ReasonKE, full updated memory (R-ALL) | 21/24 | 3 | 0 |
| Qwen, updated retrieval (G-RAG) | 24/24 | 0 | 0 |
| Qwen, full updated memory (G-ALL) | 22/24 | 1 | 1 |

All 120 requests executed, with no execution errors or unexecuted records. R0's
12 applicable answers match old truth and are stale under the updated targets;
its 12 locality answers are correct. This diagnostic does not establish that the
initial model misunderstood its supplied initial world.

The existing ReasonKE deployment selected **retrieved context** before final
inference because it answered 24/24 compared with 21/24 under full memory. The
selection is recorded in `configs/deployment-policy.json` and the final protocol.
Both updated-retrieval configurations were correct on this small development
sample, so no ReasonKE superiority or universal accuracy is claimed. Qwen was
substantially faster in the matched measurements.

## Raw evidence and reproduction

- `development-reasonke.json`: 72 requests, including prompts' SHA-256 digests,
  supplied fact IDs, raw outputs, resource measurements and every outcome.
- `development-instruction.json`: 48 requests with the same question population.
- `results.json`: aggregate exported from Colab, independently recomputed on the
  host; condition, paired-comparison and record counts agree.
- `derived/`: a reproducible report, CSV, five PNG/SVG figures and figure hashes,
  generated by `scripts/build_operations_report.py` without model inference.

The inference source is `e4f82a3e6d25b99464327dded2052719446db028`.
The ReasonKE checkpoint is `YukinoKaren/ReasonKE_plus` at
`ceaedc2ae7c8fed6257953587d991ce550db6106`; Qwen is the official
`Qwen/Qwen2.5-7B-Instruct` at `a09a35458c702b33eeacc393d103063234e8bc28`.
Both ran sequentially on one Tesla T4 with NF4 weights, FP16 compute and greedy
decoding, using the fixed configuration and pinned inputs in each receipt.
Their exact checkpoint ancestry is not verified; this comparison does not
isolate a causal effect of ReasonKE training. No training ran in this study.

## What failed and what the measurements mean

ReasonKE full memory returned an old team's contact for two two-hop questions
and applied a release-2 owner to a release-1 question. Qwen full memory selected
the similarly named service's owner once and abstained on a two-hop paraphrase.
These outcomes remain in both the denominator and raw files. Correct targets
mentioned only inside an explanation do not earn final-answer credit.

Warm pipeline p50/p95 seconds: R0 15.45/19.71, R-RAG 15.03/16.05,
R-ALL 14.40/17.01, G-RAG 0.81/1.02, G-ALL 1.19/1.36 (24 requests each).
Timing includes context selection, local worker communication and generation;
it excludes model loading and the website HTTP round trip. Loading took 78.89
and 77.71 seconds in these cached ReasonKE/Qwen sessions. Peak CUDA reserved
memory during loading was 7,140,802,560 bytes per model.

The primary accuracy denominator includes wrong answers, abstentions and any
execution failures; coverage and answered-only precision are separate. Paired
uncertainty groups questions by lineage. Three lineages and shared templates
provide limited evidence, including a zero-width paired interval when both
methods answer all 24 correctly. Such an interval does not imply certainty on
other questions. Dataset labels were audited automatically, without independent
human review. This run was not used as a substitute for the held-out evaluation.
