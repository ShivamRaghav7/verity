The initial answer model learned to copy the corrected fact more reliably than it learned the opening Yes/No decision. A frozen diagnostic on the existing reviewed development rows reproduced the recorded validation token loss: 0.044412. Despite this low mean loss, the first answer token was correct for only 2/24 training questions requiring No and 0/12 validation questions requiring No. The model predicted Yes on every validation comparison question. These are observed development results, not final-test results or a claim about general natural-language arithmetic.

For validation questions requiring No, the first-token negative log-likelihood averaged 1.0646 while the remaining tokens averaged 0.02154. First tokens constituted 5.6% of those target tokens and 74.6% of their loss. Teacher forcing supplies the preceding gold answer tokens, so the easily copied continuation can have low loss even when the free-running answer starts incorrectly. The same polarity failure occurs in the original dataset context and in the recorded runtime supporting context. The evidence supports testing a different objective; it does not prove that the original objective is the sole cause.

The opt-in `comparison_first_token_8x` objective makes one bounded change. The first target token receives weight 8 for each reviewed comparison row with an explicit expected polarity of `yes` or `no`; both labels receive the same weight. All other valid target tokens receive weight 1 and padding receives weight 0. For a batch, the loss is the sum of weighted token cross-entropies divided by the sum of token weights. The model still receives the complete, unchanged gold target through its ordinary teacher-forcing path. No catalogue fact, question, answer target, split or review is rewritten.

The factor 8 is fixed for this revision. It makes a comparison decision contribute roughly one third of the weighted token denominator of an approximately 18-token answer, instead of approximately one eighteenth. It is an engineering hypothesis selected for a single development revision, not the result of a hyperparameter sweep. The remaining fact tokens retain substantial weight. The revision may still fail to learn numeric comparisons; the same questions must be evaluated and failures retained.

The default `uniform` policy uses the model's original loss calculation unchanged for both tasks. The scope model rejects the opt-in answer objective, and unknown policies fail before optimizer creation. The weighted policy requires accepted reviewed row metadata, a recognized question type, right-padded targets beginning at position zero, and a first target token that agrees with an independently tokenized, single-token Yes or No label. Malformed masks, interior padding, non-finite weights and non-comparison polarity metadata are rejected.

Objective policy, weight, normalization and version are recorded in the training identity and manifest. The configuration hash binds the run card, and checkpoints carry the objective identity. Changing the objective cannot resume an earlier run. Training logs disclose the objective and batch weight denominator; validation aggregates the same weighted objective across all batches by their weight denominators. Checkpoint selection for this revision is labelled `validation_weighted_token_loss`. Its value is not directly comparable to the initial model's uniform validation loss and must never be reported as accuracy.

After training, frozen evaluation must separately report ordinary unweighted token loss, first-token polarity performance, complete generated-answer correctness and end-to-end behavior. A lower weighted loss alone does not establish an improvement. The archived original model and its measurements remain unchanged.

The new regression checks compare the numerical loss and gradients with an independent formula, verify equal Yes/No treatment and padding, test denominator aggregation, reject malformed metadata before optimization, and compare a tiny CPU run with exact checkpoint recovery. These checks verify implementation; they do not substitute for evaluation of the trained answer model.
